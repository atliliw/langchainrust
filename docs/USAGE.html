LLM

直接调用 LLM

rust 
use langchainrust::{OpenAIChat, OpenAIConfig, BaseChatModel};
use langchainrust::schema::Message;

// 创建配置
let config = OpenAIConfig {
    api_key: std::env::var("OPENAI_API_KEY")?,
    base_url: "https://api.openai.com/v1".to_string(),
    model: "gpt-3.5-turbo".to_string(),
    ..Default::default()
};

let llm = OpenAIChat::new(config);

let messages = vec![
    Message::system("你是一个友好的助手。"),
    Message::human("什么是 Rust 语言？"),
];

let response = llm.chat(messages, None).await?;
println!("{}", response.content);

流式输出

💡 提示
流式输出让用户实时看到生成过程，感知延迟更低。
rust 
let config = OpenAIConfig {
    streaming: true,  // 启用流式
    ..Default::default()
};

let mut stream = llm.stream_chat(messages, None).await?;

while let Some(chunk) = stream.next().await {
    if let Ok(token) = chunk {
        print!("{}", token);  // 实时打印
    }
}

流式 vs 非流式对比

方式 延迟 适用场景
chat() 等待完整响应（5-10秒） 批量处理、后台任务
stream_chat() 首token立即显示（0-500ms） 实时交互、聊天界面

Memory

四种 Memory 类型解决对话历史管理：

BufferMemory
无压缩

保存全部对话，适合短对话。

WindowMemory
窗口截断

只保留最近 k 轮对话。

SummaryMemory
LLM摘要

智能压缩，节省 token。

SummaryBufferMemory
推荐 混合策略

摘要 + 保留最近对话。

Memory 压缩方式 Token控制 适用场景
BufferMemory无无限短对话
WindowMemory硬删除固定k轮简单控制
SummaryMemoryLLM摘要动态长对话
SummaryBufferMemory摘要+保留动态+最近平衡方案

Agent

FunctionCallingAgent
推荐

原生 Function Calling，类型安全，可靠性高。

  • GPT-4 / Claude / Gemini
  • JSON Schema 类型安全
  • 低 token 消耗
ReActAgent
兼容旧模型

文本解析方式，适用于不支持 FC 的模型。

  • 本地部署模型
  • 开源模型
  • 正则提取参数

创建 FunctionCallingAgent

rust 
let tools: Vec> = vec![
    Arc::new(Calculator::new()),
    Arc::new(DateTimeTool::new()),
];

let agent = FunctionCallingAgent::new(llm, tools.clone(), None);
let executor = AgentExecutor::new(Arc::new(agent), tools)
    .with_max_iterations(5);

let result = executor.invoke("计算 37 + 48").await?;

RAG

检索增强生成：向量检索 + Agent 结合

✓ 关键步骤
  • 检索：从向量数据库检索 top_k 个相关文档
  • 构建上下文：将文档格式化为 prompt 上下文
  • 调用 LLM：将问题和上下文一起发送给模型
  • 返回答案：模型基于上下文生成答案

LangGraph

图状工作流框架，用于构建复杂的 AI 应用流程。

StateGraph
状态图

节点间共享状态，构建复杂流程。

条件边
动态路由

根据状态决定下一步分支。

Human-in-the-loop
关键

关键节点暂停等待人工确认。

Subgraph
嵌套

子图嵌套，模块化复杂流程。

Parallel
并行

并行执行多个独立任务。

Checkpointer
持久化

保存执行状态，支持恢复。

StateGraph 基用法

rust 
use langchainrust::langgraph::{StateGraph, AgentState, START, END};

let mut graph = StateGraph::new();

// 添加节点
graph.add_node("analyze", |state: AgentState| {
    let mut new_state = state.clone();
    new_state.steps.push("已分析".to_string());
    new_state
});

graph.add_node("process", |state: AgentState| {
    let mut new_state = state.clone();
    new_state.steps.push("已处理".to_string());
    new_state
});

// 添加边
graph.add_edge(START, "analyze");
graph.add_edge("analyze", "process");
graph.add_edge("process", END);

// 编译并执行
let compiled = graph.compile();
let result = compiled.invoke(AgentState::new()).await?;

条件边路由

rust 
use langchainrust::langgraph::{ConditionalEdge, FunctionRouter};

// 路由函数
let router = FunctionRouter::new(|state: &AgentState| {
    if state.messages.len() > 5 {
        "summarize"
    } else {
        "continue"
    }
});

// 添加条件边
graph.add_conditional_edge(
    "analyze",
    ConditionalEdge::new(router, vec!["summarize", "continue"]),
);

Human-in-the-loop

⚡ 关键应用
  • AI 审批流程：AI 分析后等待人工确认
  • 代码生成：生成代码后等待人工 review
  • 自动化运维：执行关键操作前等待确认
rust 
// 设置中断点
let compiled = graph.compile()
    .with_interrupt_before(vec!["output"])
    .with_interrupt_after(vec!["analyze"]);

let execution = compiled.invoke_with_execution(state).await?;

if execution.is_interrupted() {
    println!("暂停在节点: {}", execution.current_node);
    
    // 人工确认后继续
    if user_approval() {
        let result = compiled.resume(execution).await?;
    }
}

Parallel 并行执行

rust 
// Fan-Out: 分发到多个并行节点
graph.add_edge("dispatch", "task_a");
graph.add_edge("dispatch", "task_b");
graph.add_edge("dispatch", "task_c");

// Fan-In: 汇聚到一个节点
graph.add_edge("task_a", "merge");
graph.add_edge("task_b", "merge");
graph.add_edge("task_c", "merge");

let compiled = graph.compile().with_parallel_execution(true);
let result = compiled.invoke_parallel(state).await?;

Agents

Agent 是 LangChainRust 的核心组件，使 LLM 能够自主决策、调用工具并执行多步骤任务。

核心价值：将复杂问题分解为步骤，自动选择合适工具，迭代直至任务完成。

自主决策

Agent 根据问题和工具描述决定下一步行动

工具调用

Calculator、DateTime、URLFetch 等

迭代执行

观察工具输出并继续思考

类型安全

FunctionCallingAgent 使用原生 FC

FunctionCallingAgent（推荐）

适用场景

支持 Function Calling 的模型（GPT-4、Claude、Gemini 等）

rust 
use langchainrust::{
    FunctionCallingAgent, AgentExecutor, BaseAgent, BaseTool,
    OpenAIChat, OpenAIConfig, Calculator, DateTimeTool,
};

let config = OpenAIConfig {
    api_key: std::env::var("OPENAI_API_KEY")?,
    model: "gpt-4".to_string(),
    ..Default::default()
};
let llm = OpenAIChat::new(config);

let tools: Vec> = vec![
    Arc::new(Calculator::new()),
    Arc::new(DateTimeTool::new()),
];

let agent = FunctionCallingAgent::new(llm, tools.clone(), None);
let executor = AgentExecutor::new(Arc::new(agent), tools)
    .with_max_iterations(5);

let result = executor.invoke("Calculate 37 + 48").await?;

ReActAgent（兼容旧模型）

适用场景

不支持 Function Calling 的模型（开源模型、本地部署）

rust 
let tools: Vec> = vec![
    Arc::new(Calculator::new()),
    Arc::new(DateTimeTool::new()),
];

let agent = ReActAgent::new(llm, tools.clone(), None);
let executor = AgentExecutor::new(Arc::new(agent), tools)
    .with_max_iterations(5);

LCEL v0.15.0

LCEL (LangChain Expression Language) 提供管道组合语法，将 Runnable 组件通过 pipe() 串联成流水线，类似 Python LangChain 的 prompt | llm | parser。

核心价值：声明式组合、类型安全、统一 invoke/batch/stream/transform 接口。

RunnableSequence

管道执行：pipe() 串联

RunnableLambda

闭包包装：sync/async

RunnablePassthrough

透传：真流式

RunnableParallel

扇出/扇入

RunnableBranch

条件路由

RunnableBinding

配置/kwargs 绑定

管道组合示例

Rust 
use langchainrust::{RunnableExt, RunnableLambda, RunnableParallel};

let doubler = RunnableLambda::new_sync(|x: i32| x * 2);
let formatter = RunnableLambda::new_sync(|x: i32| format!("Result: {}", x));

// 管道组合
let chain = doubler.pipe(formatter);
let result = chain.invoke(5, None).await?;
// result = "Result: 10"

// 并行执行
let parallel = RunnableParallel::new()
    .with("double", RunnableLambda::new_sync(|x: i32| x * 2))
    .with("triple", RunnableLambda::new_sync(|x: i32| x * 3));
let result = parallel.invoke(5, None).await?;
// result = {"double": 10, "triple": 15}

Document Chains

文档处理链通过结合 LLM 调用与不同策略来处理多文档：Stuff、Refine、MapReduce 和 MapRerank。

核心价值：以不同的速度、成本和质量权衡处理大量文档。

策略方式适用场景Token 用量
Stuff将所有文档拼接到一个 Prompt 中小文档集、简单任务最低
Refine逐文档迭代优化答案顺序推理任务中等
MapReduce对每个文档 Map，再 Reduce 合并大文档集、可并行高
MapRerank对每个文档 Map 并评分，选最佳事实准确性优先高

StuffDocumentsChain

rust 
use langchainrust::chains::StuffDocumentsChain;

let chain = StuffDocumentsChain::new(llm);

let docs = vec![
    Document::new("Rust is memory-safe without a garbage collector."),
    Document::new("It provides zero-cost abstractions."),
];

let result = chain.invoke_with_documents(
    docs,
    "What are Rust's key features?",
).await?;

RefineDocumentsChain

rust 
use langchainrust::chains::RefineDocumentsChain;

let chain = RefineDocumentsChain::new(llm);

let result = chain.invoke_with_documents(
    docs,
    "Summarize Rust features",
).await?;

MapReduceDocumentsChain

rust 
use langchainrust::chains::MapReduceDocumentsChain;

let chain = MapReduceDocumentsChain::new(llm);

let result = chain.invoke_with_documents(
    docs,
    "Summarize the key points",
).await?;

MapRerankDocumentsChain

rust 
use langchainrust::chains::MapRerankDocumentsChain;

let chain = MapRerankDocumentsChain::new(llm);

let result = chain.invoke_with_documents(
    docs,
    "Rank and summarize the most relevant points",
).await?;

let result = chain.invoke(HashMap::from([
    ("input_documents", docs),
    ("question", "What is the most important feature?"),
])).await?;
✓ 策略选择指南
  • Stuff — 少量小文档、简单查询（最快、最省）
  • Refine — 顺序构建上下文，每篇文档在前一答案基础上优化
  • MapReduce — 大量文档、并行处理后再合并
  • MapRerank — 事实准确性要求高时，按评分选最佳答案

Memory

对话记忆 管理 Agent 或 Chain 的对话历史，控制 Token 消耗。

记忆类型压缩方式Token 控制适用场景
BufferMemory无压缩无限制短对话
WindowMemory窗口截断固定 k 轮简单控制
SummaryMemoryLLM 摘要智能压缩长对话
SummaryBufferMemory摘要 + 保留动态推荐

ConversationBufferMemory

rust 
let mut memory = ConversationBufferMemory::new();

let inputs = HashMap::from([("input".to_string(), "My name is John".to_string())]);
let outputs = HashMap::from([("output".to_string(), "Hello John!".to_string())]);
memory.save_context(&inputs, &outputs).await?;

let vars = memory.load_memory_variables(&HashMap::new()).await?;
// Output: "Human: My name is John\nAI: Hello John!"
⚠️ SummaryMemory 成本警告

每轮对话都会调用 LLM 生成摘要。100 轮 = 100 次 LLM 调用。请谨慎评估成本。

自定义工具

rust 
use langchainrust::core::tools::{BaseTool, ToolError};
use schemars::JsonSchema;
use serde::Deserialize;

#derive[JsonSchema, Deserialize]
struct WeatherInput { city: String }

pub struct WeatherTool;

#async_trait
impl BaseTool for WeatherTool {
    fn name(&self) -> &str { "weather" }
    
    fn description(&self) -> &str {
        "Query city weather"
    }
    
    async fn run(&self, input: String) -> Result<String, ToolError> {
        let args: WeatherInput = serde_json::from_str(&input)?;
        Ok(format!("{} weather: Sunny, 25°C", args.city))
    }
}

RAG

检索增强生成 先从知识库检索相关文档，再让 LLM 基于检索内容生成答案。

核心价值：让 LLM 无需重新训练即可访问私有知识库和最新数据。

文档加载

PDF、CSV 等

智能分割

RecursiveCharacterSplitter

向量嵌入

OpenAI Embeddings

语义检索

基于向量相似度

完整 RAG 流程

rust 
use langchainrust::{
    Document, InMemoryVectorStore, MockEmbeddings,
    SimilarityRetriever, RecursiveCharacterSplitter,
};

// 1. Prepare documents
let docs = vec![
    Document::new("Rust is a systems programming language..."),
];

// 2. Split documents
let splitter = RecursiveCharacterSplitter::new(200, 50);
let chunks = splitter.split_documents(&docs)?;

// 3. Create retriever
let retriever = SimilarityRetriever::new(store, embeddings);
retriever.add_documents(chunks).await?;

// 4. Execute QA
let qa_chain = RetrievalQA::new(llm, retriever);
let result = qa_chain.invoke(inputs).await?;

RAG 配置

参数推荐值说明
chunk_size200-500每个分块的最大字符数
overlap50-100相邻分块之间的重叠
top_k3-10检索文档数量

BM25

关键词检索 是经典的 TF-IDF 加权检索算法，通过词频和逆文档频率计算文档与查询的相关性评分。

核心价值： 不依赖 Embedding，适合关键词精确匹配和专业术语搜索。

关键词匹配

精确匹配，无语义理解

中英文分词

英文空格分词 + 中文二元分词

停用词过滤

自动过滤常见停用词

参数可调

k1 饱和度、b 归一化

BM25Retriever 基础用法

rust 
use langchainrust::{BM25Retriever, Document};

let retriever = BM25Retriever::new();

retriever.add_documents_sync(vec![
    Document::new("Rust is a systems programming language"),
    Document::new("Python is a scripting language"),
]);

let results = retriever.search("systems programming", 3);

BM25 参数配置

参数默认值说明
k11.5词频饱和度
b0.75文档长度归一化

Hybrid Retrieval

混合检索 结合 BM25 的关键词匹配能力和向量检索的语义理解能力，通过 RRF 算法融合结果。

核心价值： 关键词精确匹配 + 语义理解，召回率更高。

BM25 检索

关键词精确匹配

向量检索

语义相似度匹配

RRF 融合

基于排名的融合算法

统一索引

一次添加，构建双索引

RRF 融合算法

RRF (Reciprocal Rank Fusion)

RRF_score(d) = Σ 1/(k + rank(d))

k 通常取 60，rank(d) 为文档排名。

UnifiedHybridIndex 使用

rust 
use langchainrust::{UnifiedHybridIndex, HybridIndexConfig, InMemoryVectorStore, VectorStore};

let config = HybridIndexConfig::new()
    .with_chunk_size(500)
    .with_top_k(10, 10);

let vector_store: Arc = Arc::new(InMemoryVectorStore::new());
let index = UnifiedHybridIndex::with_config(embeddings, vector_store, 1536, config);

// Auto-build BM25 + Vector dual index
index.add_document(Document::new("Document content")).await?;

// Hybrid retrieval
let results = index.retrieve("query", 5).await?;

检索方式对比

方式匹配召回率适用场景
关键词检索关键词精确中等专业术语搜索
向量检索语义相似中等意图理解
混合检索双重融合高通用搜索

三种检索模式架构

核心区别

LangChainRust 提供三种检索模式，各有不同的内容存储和查找策略：

模式内容存储查找适用场景
SimpleVector 内容直接存储在 InMemoryVectorStore 中 ❌ 无查找 仅向量检索，简单快速
仅 BM25 内容在 ChunkedDocumentStore，BM25 仅存词频 ✅ 可查找 仅关键词检索
混合 BM25 + 向量共享 ChunkedDocumentStore ✅ 可查找 混合搜索，内容共享
✓ 查找设计的优势
  • 索引更小：BM25/向量仅存储统计信息和嵌入，不存内容
  • 内容共享：BM25 和向量共享同一份内容，避免重复
  • 自动合并：父子结构，匹配时自动合并

ChromaDB 向量存储

rust 
use langchainrust::vector_stores::{ChromaDBVectorStore, ChromaDBConfig};

// Create ChromaDB store

Storage Backends

ChunkedDocumentStoreTrait 提供统一的存储接口，支持 Redis 和 SQLite 后端用于生产级文档存储。

核心价值：持久化、可扩展的文档存储，超越纯内存方案。

后端特性适用场景启用方式
InMemory 内存存储，零依赖 开发/测试、小规模 默认
MongoDB 持久化、分片、生产就绪 大规模生产 feature = mongodb-persistence
Redis 超快内存缓存，可选持久化 高频访问、缓存 feature = redis-persistence
SQLite 轻量级、本地文件、零配置 本地/嵌入式、单用户 feature = sqlite-persistence

Redis 存储

rust 
use langchainrust::vector_stores::{RedisDocumentStore, RedisStoreConfig, DocumentStore};

// Cargo.toml: langchainrust = { features = ["redis-storage"] }
let store = RedisDocumentStore::new(
    RedisStoreConfig::new("redis://127.0.0.1:6379")
).await?;

let id = store.add_document(doc).await?;

// Retrieve by id
let doc = store.get_document(&id).await?;

SQLite 存储

rust 
use langchainrust::vector_stores::{SQLiteDocumentStore, SQLiteStoreConfig, DocumentStore};

// Cargo.toml: langchainrust = { features = ["sqlite-storage"] }
let store = SQLiteDocumentStore::new(
    SQLiteStoreConfig::new("./data/store.db")  // local SQLite file

统一接口

所有存储后端均实现 ChunkedDocumentStoreTrait，可无缝切换而无需修改应用代码。

FewShotPromptTemplate

0.2.18 新增

将示例输入-输出对注入提示词，通过少样本学习引导 LLM 行为。

rust 
use langchainrust::prompts::{FewShotPromptTemplate, PromptTemplate};

let examples = vec![
    HashMap::from([
        ("question", "What is the capital of France?"),
        ("answer", "Paris"),
    ]),
    HashMap::from([
        ("question", "What is 2+2?"),
        ("answer", "4"),
    ]),
];

let template = FewShotPromptTemplate::new(
    examples,
    PromptTemplate::new("Question: {question}\nAnswer: {answer}"),  // example prompt
    "Few-shot examples:",     // prefix
    "Question: {input}",      // suffix
    vec!["input".to_string()],   // input variables
);

let vars = HashMap::from([
    ("input", "What is the capital of Japan?"),
]);

let prompt = template.format(&vars)?;
// Question: What is the capital of France?
// Answer: Paris
// Question: What is 2+2?
// Answer: 4
// Question: What is the capital of Japan?
✓ 何时使用 FewShot
  • 引导输出格式（如 JSON、XML）
  • 教会模型特定的推理模式
  • 设定语气、风格或领域特定约定

LLM 缓存缓存 LLM 响应，减少 API 调用、降低成本、改善重复查询的响应延迟。

核心价值：缓存相同请求，重复查询可降低高达 90% 的 API 成本。

手动旁路

build_key 判键、get/put 读写，接入自定义路径

内存 LLM 缓存

rust 
use langchainrust::core::cache::{CacheConfig, LLMCache};
use std::time::Duration;

// Configure the cache (TTL + entry cap)
let cache = LLMCache::with_config(
    CacheConfig::new().with_ttl(Duration::from_secs(3600))
);

// LLMCache 是独立组件,手动接入调用路径:build_key 判键,get/put 读写
let messages = vec![Message::human("What is Rust?")];
let key = LLMCache::build_key(&messages, "gpt-4o")?;

let result = if let Some(hit) = cache.get(&key).await {
    hit.result
} else {
    let fresh = llm.chat(messages, None).await?;
    cache.put(key, fresh.clone()).await;
    fresh
};
✓ 缓存最佳实践
  • 确定性查询：相同输入始终需要相同输出时缓存效果最佳
  • TTL 调优：根据数据新鲜度需求设置合适的 TTL
  • 容量上限：用 with_max_entries 限制条目，防止内存膨胀

Best Practices

01 Agent 选择

优先使用 FunctionCallingAgent（更可靠），本地模型用 ReActAgent。

02 模型选择

Agent 推荐 gpt-4，简单对话用 gpt-3.5-turbo，多模态用 Gemini。

03 记忆选择

长对话用 SummaryBufferMemory，短对话用 BufferMemory，超长用 ContextWindow。

04 RAG 策略

简单用 RetrievalQA，质量要求高用 CorrectiveRAG，关系密集用 GraphRAG，自适应用 AdaptiveRAG。

05 模型路由

可靠性用 Fallback 策略，成本用 LowestCost，速度用 LeastLatency。

06 缓存

重复查询启用 LLM 缓存，离线批量处理用 Batch API（成本降 50%）。

07 文档策略

少量小文档用 Stuff，大量文档用 MapReduce，精度要求高用 MapRerank，关系密集用 GraphRAG。

08 可观测性

生产环境用 Tracing (Tracer + SpanGuard) 监控，分布式追踪用 OTel 后端。

09 安全

用 Guardrails 做输入/输出验证，API Key 用环境变量，绝不硬编码。

10 CRAG 评分

用 with_grader_llm() 注入不同 LLM 做幻觉检测，避免自我验证偏差。

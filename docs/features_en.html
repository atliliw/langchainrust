Agents

Agent is LangChainRust's core component that enables LLMs to autonomously decide, call tools, and execute multi-step tasks.

Core value: Break complex problems into steps, automatically select appropriate tools, iterate until task completion.

Autonomous Decision

Agent decides next action based on question and tool descriptions

Tool Calling

Calculator, DateTime, URLFetch and more

Iterative Execution

Observe tool output and continue thinking

Type Safety

FunctionCallingAgent uses native FC

FunctionCallingAgent (Recommended)

Use Case

Models supporting Function Calling (GPT-4, Claude, Gemini, etc.)

rust 
use langchainrust::{
    FunctionCallingAgent, AgentExecutor, BaseAgent, BaseTool,
    OpenAIChat, OpenAIConfig, Calculator, DateTimeTool,
};

let config = OpenAIConfig {
    api_key: std::env::var("OPENAI_API_KEY")?,
    model: "gpt-4".to_string(),
    ..Default::default()
};
let llm = OpenAIChat::new(config);

let tools: Vec> = vec![
    Arc::new(Calculator::new()),
    Arc::new(DateTimeTool::new()),
];

let agent = FunctionCallingAgent::new(llm, tools.clone(), None);
let executor = AgentExecutor::new(Arc::new(agent), tools)
    .with_max_iterations(5);

let result = executor.invoke("Calculate 37 + 48").await?;

Use Case

Memory manages Agent or Chain conversation history, controlling Token consumption.

MemoryCompressionToken ControlUse Case
BufferMemoryNo compressionUnlimitedShort conversations
WindowMemoryWindow truncationFixed k roundsSimple control

SummaryBufferMemorySummary + retainDynamicRecommended

ConversationBufferMemory

rust 
let mut memory = ConversationBufferMemory::new();

let inputs = HashMap::from([("input", "My name is John")]);
let outputs = HashMap::from([("output", "Hello John!")]);
memory.save_context(&inputs, &outputs).await?;

let vars = memory.load_memory_variables(&HashMap::new()).await?;
// Output: "Human: My name is John\nAI: Hello John!"
⚠️ SummaryMemory Cost Warning

Each conversation round calls LLM for summary. 100 rounds = 100 LLM calls. Evaluate costs carefully.

Custom Tool

rust 
use langchainrust::core::tools::{BaseTool, ToolError};
use schemars::JsonSchema;
use serde::Deserialize;

#derive[JsonSchema, Deserialize]
struct WeatherInput { city: String }

pub struct WeatherTool;

#async_trait
impl BaseTool for WeatherTool {
    fn name(&self) -> &str { "weather" }
    
    fn description(&self) -> &str {
        "Query city weather"
    }
    
    async fn run(&self, input: String) -> Result<String, ToolError> {
        let args: WeatherInput = serde_json::from_str(&input)?;
        Ok(format!("{} weather: Sunny, 25°C", args.city))
    }
}

RAG

RAG retrieves relevant documents from knowledge base first, then lets LLM generate answers based on retrieved content.

Core value: Let LLM access private knowledge base and latest data without retraining.

Document Loading

PDF, CSV, and more

Smart Splitting

RecursiveCharacterSplitter

Vector Embedding

OpenAI Embeddings

Semantic Retrieval

Vector similarity based

Complete RAG Workflow

rust 
use langchainrust::{
    Document, InMemoryVectorStore, MockEmbeddings,
    SimilarityRetriever, RecursiveCharacterSplitter,
};

// 1. Prepare documents
let docs = vec![
    Document::new("Rust is a systems programming language..."),
];

// 2. Split documents
let splitter = RecursiveCharacterSplitter::new(200, 50);
let chunks = splitter.split_documents(&docs)?;

// 3. Create retriever
let retriever = SimilarityRetriever::new(store, embeddings);
retriever.add_documents(chunks).await?;

// 4. Execute QA
let qa_chain = RetrievalQA::new(llm, retriever, 3);
let result = qa_chain.invoke(inputs).await?;

RAG Configuration

ParameterRecommendedDescription
chunk_size200-500Max characters per chunk
overlap50-100Overlap between adjacent chunks

BM25

BM25 is a classic TF-IDF weighted retrieval algorithm, calculating relevance scores via term frequency and inverse document frequency.

Core value: No embedding dependency, ideal for keyword matching and technical term search.

Keyword Matching

Exact match, no semantic understanding

Tokenization

English whitespace + Chinese bigram

Stopwords

Auto filter common stopwords

Tunable Params

k1 saturation, b normalization

BM25Retriever Usage

rust 
use langchainrust::{BM25Retriever, Document};

let mut retriever = BM25Retriever::new();

retriever.add_documents_sync(vec![
    Document::new("Rust is a systems programming language"),
    Document::new("Python is a scripting language"),
]);

let results = retriever.search("systems programming", 3);

BM25 Parameters

ParameterDefaultDescription
k11.5Term frequency saturation
b0.75Document length normalization

Hybrid Retrieval

Hybrid Retrieval combines BM25 keyword matching + Vector semantic understanding via RRF fusion algorithm.

Core value: Keyword precision + semantic understanding, higher recall rate.

BM25 Search

Keyword exact matching

Vector Search

Semantic similarity matching

RRF Fusion

Rank-based fusion algorithm

Unified Index

Add once, build dual index

RRF Fusion Formula

RRF (Reciprocal Rank Fusion)

RRF_score(d) = Σ 1/(k + rank(d))

k typically 60, rank(d) is document rank.

UnifiedHybridIndex Usage

rust 
use langchainrust::{UnifiedHybridIndex, HybridIndexConfig};

let config = HybridIndexConfig::new()
    .with_chunk_size(500)
    .with_top_k(10, 10);

let index = UnifiedHybridIndex::with_config(embeddings, 1536, config);

// Auto-build BM25 + Vector dual index
index.add_document(Document::new("Document content")).await?;

// Hybrid retrieval
let results = index.retrieve("query", 5).await?;

Three Retrieval Modes Architecture

Key Difference

LangChainRust provides three retrieval modes with different content storage and lookup strategies:

ModeContent StorageLookupUse Case
SimpleVector Content stored directly in InMemoryVectorStore ❌ No lookup Vector-only, simple & fast
BM25 Only Content in ChunkedDocumentStore, BM25 stores term freq only ✅ Lookup Keyword-only retrieval
Hybrid BM25 + Vector share ChunkedDocumentStore ✅ Lookup Hybrid search, content shared
✓ Benefits of Lookup Design
  • Small Index: BM25/Vector store only statistics and embeddings, not content
  • Content Shared: BM25 and Vector share the same content, avoid duplication
  • AutoMerging: Parent-Child structure, auto-merge when matched

Storage Backend Options

ChunkedDocumentStoreTrait

Unified storage interface supporting multiple backends:

BackendFeaturesUse CaseEnable
InMemory In-memory, zero dependency Dev/test, small scale Default
MongoDB Persistent, sharding, production-ready Large-scale production feature = mongodb-persistence
Redis Ultra-fast, cache layer High-frequency cache Reserved
SQLite Lightweight, local file Local/embedded Reserved

MongoDB Usage

rust 
use langchainrust::{MongoChunkedDocumentStore, MongoStoreConfig};

let config = MongoStoreConfig::new(
    "mongodb://localhost:27017",
    "langchainrust_db"
);

let store = MongoChunkedDocumentStore::new(config).await?;
store.create_indexes().await?;

// Same interface as InMemory
let (parent_id, chunks) = store.add_parent_document(doc, 500).await?;

LangGraph

LangGraph is a state-graph workflow framework for building complex AI applications.

StateGraph

Shared state between nodes

Conditional Edge

Dynamic routing based on state

Human-in-loop

Pause for human approval

Subgraph

Nested graph modules

Basic Usage

rust 
use langchainrust::langgraph::{StateGraph, START, END};

let graph = GraphBuilder::new()
    .add_node("analyze", |state| { Ok(()) })
    .add_edge(START, "analyze")
    .add_edge("analyze", END)
    .build();

let result = graph.invoke(state).await?;

Parallel Execution

Fan-Out / Fan-In

Execute multiple independent nodes in parallel:

rust 
// Add parallel nodes
graph.add_node("task_a", |state| { /* ... */ });
graph.add_node("task_b", |state| { /* ... */ });
graph.add_node("task_c", |state| { /* ... */ });

// Fan-Out
graph.add_edge(START, "dispatch");
graph.add_edge("dispatch", "task_a");
graph.add_edge("dispatch", "task_b");
graph.add_edge("dispatch", "task_c");

// Fan-In
graph.add_edge("task_a", "merge");
graph.add_edge("task_b", "merge");
graph.add_edge("task_c", "merge");
graph.add_edge("merge", END);

let compiled = graph.compile().with_parallel_execution(true);
let result = compiled.invoke_parallel(state).await?;

Checkpointer (Persistence)

State Persistence

Save and restore execution state for session persistence:

rust 
use langchainrust::langgraph::{MemoryCheckpointer, FileCheckpointer};

// Memory checkpointer
let checkpointer = MemoryCheckpointer::new();

// File checkpointer
let file_checkpointer = FileCheckpointer::new("./checkpoints/");

let compiled = graph.compile().with_checkpointer(checkpointer);

// Execute with thread_id
let thread_id = "conversation_123";
let result = compiled.invoke_with_thread(state, thread_id).await?;

// Restore previous state
let previous = compiled.get_state(thread_id).await?;
let resumed = compiled.invoke_with_thread(previous, thread_id).await?;

Visualization

Three Output Formats

ASCII (terminal), Mermaid (Markdown), JSON (programmatic):

rust 
// ASCII (terminal)
println!("{}", compiled.visualize_ascii());
// START → analyze → process → END

// Mermaid (Markdown)
println!("{}", compiled.visualize_mermaid());
// graph LR: START --> analyze --> process --> END

// JSON
let json = compiled.visualize_json();
// {"nodes": [...], "edges": [...]}

Graph Validation

Auto-Detection

Automatically detect common issues:

Task Planning

TaskPlanner automatically decomposes complex tasks into subtasks, executes sequentially, then aggregates results.

Core value: Auto decompose complex tasks, multi-step execution with result aggregation.

Task Decomposition

TaskPlanner analyzes and splits complex tasks

Sequential Execution

PlannedExecutor runs each subtask

Result Aggregation

Summarize all subtask results

Dependency Control

Subtasks can depend on previous results

TaskPlanner Example

rust 
use langchainrust::agent::TaskPlanner;

let planner = TaskPlanner::new(llm)
    .with_max_sub_tasks(5)
    .with_verbose(true);

let plan = planner.plan("Analyze code, write tests, run tests").await?;

for task in &plan.sub_tasks {
    println!("[{}] {}", task.id, task.description);
}

PlannedExecutor

Auto Workflow

Plan → Execute → Aggregate automatically:

rust 
use langchainrust::agent::{PlannedExecutor, ReActAgent};

let executor = PlannedExecutor::new(llm, agent, tools)
    .with_max_sub_tasks(3)
    .with_max_iterations(2)
    .with_verbose(true);

let result = executor
    .run("Research async best practices, write code, explain")
    .await?;

Retrieval + Agent (RAG)

Combine vector retrieval with Agent to implement RAG functionality.

Core value: Retriever provides context, Agent answers based on context.

with_retriever Usage

rust 
use langchainrust::retrieval::{Document, SimilarityRetriever};
use langchainrust::agent::ReActAgent;

// 1. Prepare documents
let docs = vec![
    Document::new("Rust is a systems language..."),
];

// 2. Create retriever
let retriever = SimilarityRetriever::new(store, embedding);
retriever.add_documents(chunks).await?;

// 3. Create RAG Agent
let agent = ReActAgent::with_retriever(
    llm,
    tools,
    memory,
    retriever,
    3  // top_k
);

// 4. Execute
let result = executor.run_with_details("What is Rust?").await?;

Best Practices

01 Agent Selection

Use FunctionCallingAgent first (more reliable). Use ReActAgent for local models.

02 Model Selection

Agents: gpt-4 recommended. Simple chat: gpt-3.5-turbo.

03 Memory Selection

Long conversations: SummaryBufferMemory. Short: BufferMemory.

04 RAG Config

chunk_size=200-500, overlap=50-100, top_k=3-10

05 Streaming

Use stream_chat() for interactive scenarios to reduce perceived latency.

06 Security

Use environment variables for API keys. Never hardcode.

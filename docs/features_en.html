First chat (Hello World)

rust 
use langchainrust::{BaseChatModel, OpenAIChat, OpenAIConfig};
use langchainrust::schema::Message;

async fn main() -> Result<(), Box> {
    let llm = OpenAIChat::new(OpenAIConfig {
        api_key: std::env::var("OPENAI_API_KEY")?,
        base_url: std::env::var("OPENAI_BASE_URL")
            .unwrap_or_else(|_| "https://api.openai.com/v1".to_string()),
        model: "gpt-4o-mini".to_string(),
        ..Default::default()
    });

    let response = llm.chat(
        vec![
            Message::system("You are a concise Rust assistant."),
            Message::human("Explain in one sentence what Rust is."),
        ],
        None,
    ).await?;

    println!("{}", response.content);
    Ok(())
}

Compose a chain with LCEL

Runnables compose with .pipe(): prompt.pipe(llm).pipe(parser) is a complete chain — one call returns the final answer. StrOutputParser extracts content from LLMResult, so the chain's output type becomes String.

rust 
use langchainrust::{ChatPromptTemplate, Message, OpenAIChat, Runnable, StrOutputParser};

let prompt = ChatPromptTemplate::from_messages([
    Message::system("You are a concise Rust assistant."),
    Message::human("{question}"),
]);

let chain = prompt.pipe(llm).pipe(StrOutputParser::new());

let mut vars = HashMap::new();
vars.insert("question".to_string(), "What is the ownership system?".to_string());
let answer: String = chain.invoke(vars, None).await?;
println!("{answer}");

2.2 with_structured_output

Give a schema, get a typed object in one step.Instead of "prompt for JSON → parse → fix errors → convert to a type", the framework packages the whole flow: pass a struct deriving JsonSchema and receive a type-safe, compile-time-verifiable result.

Provider method (recommended)

chat.with_structured_output::<T>() on OpenAIChat / OpenAICompatibleChat / OllamaChat binds the schema as a strict tool declaration, returns a method object synchronously, and parses T from the structured tool arguments on invoke

StructuredOutputExt generic trait

Auto-implemented for every BaseChatModel; takes a hand-written JSON Schema + prompt, injects it into the system message, and deserializes after the JsonOutputParser strips markdown fences and tolerates fixes

2.3a Prompt Registry

PromptRegistry gives prompts an append-only, addressable, auditable registry, built on the trio of namespace + version + content hash. It solves prompts scattered around, "which edit made it worse online, hard to say", and rollback requiring a release.

Core value: manage prompts responsibly — each register computes an SHA-256, version + hash are addressable, rollback republishes history as a new version, the audit chain never breaks.

Namespace

Slash-separated path like customer/support/zh, invalid returns InvalidNamespace

Version + Hash

Each register carries version and content SHA-256, variables parsed at register time

Three Ways to Locate

Latest / pinned @n / by content-hash prefix, all resolvable

Thread Safe

RwLock concurrency-safe, all ops &self, share via Arc

PromptRegistry usage

rust 
use langchainrust::{PromptRegistry, VersionSpec};

let registry = PromptRegistry::new();
let v1 = registry.register("customer/support/zh", "You are support. Q: {question}")?;
let v2 = registry.register("customer/support/zh", "You are senior support, empathize first")?;
assert_eq!(v1.version, 1);

let latest = registry.get("customer/support/zh")?;            // latest version
let pinned = registry.resolve("customer/support/zh", &1.into())?;  // pinned version
let tpl = registry.fetch("customer/support/zh@3")?;            // textual ref

Note: The registry is purely in-memory and lost on process exit; it ships no persistence, remote distribution, or auth. For cross-process sharing, persist in an app-side DB and load it at startup.

2.5 LLM Cache

LLM Cache caches LLM responses to reduce API calls, lower costs, and improve response latency for repeated queries.

Core value: Cache identical requests, reduce API costs by up to 90% for repetitive queries.

In-Memory Cache

Fast in-process caching, zero deps

TTL Expiry

Time-based cache expiration

Capacity Limit

max_entries caps entry count, prevents memory bloat

Manual Integration

build_key to key and get/put to read-write, plug into your own path

InMemory LLM Cache

rust 
use langchainrust::core::cache::{CacheConfig, LLMCache};
use std::time::Duration;

// Configure the cache (TTL + entry cap)
let cache = LLMCache::with_config(
    CacheConfig::new().with_ttl(Duration::from_secs(3600))
);

// LLMCache is a standalone component: build_key to key, get/put to read/write
let messages = vec![Message::human("What is Rust?")];
let key = LLMCache::build_key(&messages, "gpt-4o")?;

let result = if let Some(hit) = cache.get(&key).await {
    hit.result
} else {
    let fresh = llm.chat(messages, None).await?;
    cache.put(key, fresh.clone()).await;
    fresh
};
✓ Cache Best Practices
  • Deterministic queries: Cache works best when same input always needs same output
  • TTL tuning: Set appropriate TTL based on data freshness requirements
  • Redis for production: Use Redis cache in multi-instance deployments

2.6 RouterLLM

RouterLLM implements BaseChatModel, routing calls across a pool of heterogeneous models with 6 strategies and automatic fallback on failure. To callers it is an ordinary chat model — a drop-in replacement.

StrategyDescriptionUse Case
FallbackPrimary first, then fallbacksReliability
RoundRobinCycle through modelsLoad balancing
LeastLatencyPick lowest EMA latencySpeed optimization
LatencyWeighted(beta) ✨v0.22.4Weighted lottery over (1/latency)^beta; untried models optimistically share the best latency; deterministic SplitMix64 drawLow latency without "starving" new models
LowestCostPick cheapest modelCost optimization
InputDirectedClosure-based selectionCustom routing

Shared budget gate

RouterBudget USD/token gate shareable across routers: pre-deducts an estimate, trips → skip paid slots while free ones stay as backstop, reconciles actual usage after the call. Error name RouterBudgetExceeded

Per-model rate limit

ModelRateLimit admission gate per slot: sliding-window RPS/RPM cap, concurrency cap, FIFO wait queue (with_max_queue / with_wait_timeout); for streaming the permit is held until the body is consumed

Three price inputs

with_cost (relative) / with_priced_model + ModelPrice (USD per 1K, 0.75/0.25 blended) / with_registry + ModelRegistry::fetch (JSON catalog)

rust 
use langchainrust::{RouterLLM, RoutingStrategy, RouterBudget, ModelRateLimit, BaseChatModel};

// Latency-weighted routing (beta=1.0: a 100ms model is ~10x more likely to be primary than a 1000ms one)
let router = RouterLLM::new(RoutingStrategy::LatencyWeighted(1.0))
    .with_model(fast_model)
    .with_model(slow_but_smart_model);

// Per-model rate limit: overflow waits in queue, then yields/cuts over to backup
let limit = ModelRateLimit::per_minute(600)
    .with_max_concurrent(20)
    .with_max_queue(32)
    .with_wait_timeout(Duration::from_secs(2));
let router = RouterLLM::new(RoutingStrategy::Fallback)
    .with_model_rate_limited(primary, limit)
    .with_model(backup);

// Shared budget: $5 / 2M tokens across several routers
let budget = RouterBudget::with_cost_and_token_limits(5.0, 2_000_000);
let router = RouterLLM::new(RoutingStrategy::LowestCost)
    .with_priced_model(paid, price)
    .with_model(free_local)
    .with_budget(budget.clone());

Pipe Composition Example

Rust 
use langchainrust::{RunnableExt, RunnableLambda, RunnableParallel};

let doubler = RunnableLambda::new_sync(|x: i32| x * 2);
let formatter = RunnableLambda::new_sync(|x: i32| format!("Result: {}", x));

// Pipe composition
let chain = doubler.pipe(formatter);
let result = chain.invoke(5, None).await?;
// result = "Result: 10"

// Parallel execution
let parallel = RunnableParallel::new()
    .with("double", RunnableLambda::new_sync(|x: i32| x * 2))
    .with("triple", RunnableLambda::new_sync(|x: i32| x * 3));
let result = parallel.invoke(5, None).await?;
// result = {"double": 10, "triple": 15}

Resilience & Control Runnables

RunnableWithFallbacks ✨v0.10.0

Give a Runnable a fallback — on failure it automatically switches to the backup and keeps going (swaps the implementation; unlike RunnableBranch on content or RunnableRetry which retries the same thing)

RunnableAssign ✨v0.10.0

RunnableParallel.assign() injects new fields into the output HashMap after the parallel output

RunnableRetry ✨v0.11.0

with_retry(RetryConfig) wraps any Runnable and retries with exponential backoff on failure

CancellationToken ✨v0.11.0

Cross-task shared cancellation flag; cancel() cancels every clone; poll is_cancelled() or await cancelled() to exit gracefully

rust 
use langchainrust::{RunnableExt, RunnableLambda};
use langchainrust::core::runnables::{RetryConfig, RetryOn, CancellationToken, RunnableConfig};

// Fallbacks: primary fails → try backups in order
let chain = primary.with_fallbacks(vec![fallback.into_runnable_any()]);

// Retry with exponential backoff, transient errors only (default)
let chain = flaky.with_retry(RetryConfig::default());

// Cancellation: inject into the Runnable config
let token = CancellationToken::new();
let config = RunnableConfig::default().with_cancellation_token(token.clone());
let result = chain.invoke(input, Some(config)).await?;
if token.is_cancelled() { /* exit gracefully */ }

Basic Usage

use langchainrust::langgraph::{GraphBuilder, StateUpdate, START, END};

let graph = GraphBuilder::new()
    .add_node_fn("analyze", |state| Ok(StateUpdate::full(state.clone())))

Parallel Execution

Fan-Out / Fan-In

Execute multiple independent nodes in parallel:

rust 
// Add parallel nodes
let mut graph = GraphBuilder::new().build();
graph.add_node_fn("task_a", |state| Ok(StateUpdate::full(state.clone())));
graph.add_node_fn("task_b", |state| Ok(StateUpdate::full(state.clone())));
graph.add_node_fn("task_c", |state| Ok(StateUpdate::full(state.clone())));

// Fan-Out
graph.add_edge(START, "dispatch");
graph.add_edge("dispatch", "task_a");
graph.add_edge("dispatch", "task_b");
graph.add_edge("dispatch", "task_c");

// Fan-In
graph.add_edge("task_a", "merge");
graph.add_edge("task_b", "merge");
graph.add_edge("task_c", "merge");
graph.add_edge("merge", END);

let compiled = graph.compile()?;
let result = compiled.invoke_parallel(state).await?;

use langchainrust::langgraph::{MemoryCheckpointer, FileCheckpointer};

6.2.11 Token-Level Embeddings (TokenLevelEmbeddings) ✨v0.21.0

An optional capability trait: implementors return (byte-offset span, L2-normalized vector) per token. It is deliberately not part of the main Embeddings trait — the capability is opt-in (detected by whether it is implemented), so providers without token-level output are never forced into the contract.

One vector per token

A regular embedding collapses a whole sentence into a single point; token-level output gives each token a vector plus its byte position in the original text

Only for token-capable models

Qwen3-Embedding / BGE-M3 / Jina v3 support token output; pooling-based models can't — which is why it stays outside the main trait

Prerequisite for late chunking

Without per-token vectors + positions, pooling tokens into chunk vectors along chunk boundaries is impossible

rust
pub trait TokenLevelEmbeddings {
    async fn embed_tokens(&self, text: &str)
        -> Result, EmbeddingError>;
}

// TokenSpan is a byte offset (multibyte-safe):
// "你好 world" → tokens[1] = TokenSpan { start: 7, end: 12 } ("world")
// The local fastembed (ONNX) path implements this capability

6.2.12 Late Chunking ✨v0.21.0

The traditional approach — chunk first, embed each chunk separately — loses full-document context per chunk. Late chunking flips it: embed the whole text once at token level, then mean-pool the token vectors per chunk boundary, so every chunk carries full-document context. Retrieval quality on long documents typically improves.

rust
use langchainrust::retrieval::late_chunking::{late_chunk, LateChunkConfig};

// Requires 0 < overlap < size
let config = LateChunkConfig::new()
    .with_chunk_size(1024)     // bytes, default 1024
    .with_chunk_overlap(128);  // bytes, default 128
config.validate()?;

// the embedder must implement TokenLevelEmbeddings (e.g. the local ONNX path)
let chunks = late_chunk(&embedder, "the whole long document...", &config).await?;
// c.range = (start, end) byte range; c.text = chunk text; c.vector = pooled, L2-normalized
⚠️ Caveat

Late chunking is not a silver bullet — self-contained short documents gain nothing; the model must support token-level output.

6.7 HyDE Retriever

HyDE (Hypothetical Document Embeddings) fixes "query too short / nthmatch with docs": the LLM first writes a hypothetical answer (possibly inaccurate), then retrieves real docs with the hypothetical answer's embedding. Because the hypothetical wording is closer to real documents, retrieval improves.

Flow: user query → LLM generates hypothetical doc → retrieve with it → return real docs.

Hypothetical Doc

LLM turns a short query into text matching the real docs' style

Embed by Base

Vectorization handled by the base retriever, no separate embedding param

Real Docs Back

Ranking happens between hypothetical↔real; real docs are returned

Dual In-Search

Optionally fold the original query in, lowering bias risk

HyDERetriever usage

rust 
use langchainrust::{HyDERetriever, SimilarityRetriever, OpenAIChat, OpenAIEmbeddings};

let base_retriever = Arc::new(SimilarityRetriever::new(store, embeddings));

    .with_k(5)

Note: The hypothetical answer may itself be wrong — it only serves to "align wording"; real retrieved docs are still what you get. The base retriever is Arc<dyn RetrieverTrait> — BM25, vector, and hybrid all work.

6.9 Contextual Retrieval

Contextual Retrieval (proposed by Anthropic) is an indexing-time enhancement: ContextualEnhancer has a small LLM generate 1-2 sentences of context for each chunk at indexing time, prepends it to the original text before storing, and retrieval hit rate rises significantly.

Core value: turn "isolated chunks" into "chunks with context", fixing recall loss from per-chunk topic fragmentation.

Idempotent

Docs already carrying contextual_context are skipped, no double-layering

Fail-Open

A single chunk LLM failure logs a warning and stores the raw text, no index blockage

Concurrency

with_max_concurrency controls parallelism, default 4

Cheap LLM

One LLM call per chunk, use a cheap small model to control cost

ContextualEnhancer usage

rust 
use langchainrust::retrieval::contextual::{ContextualConfig, ContextualEnhancer};

    .with_config(ContextualConfig::new().with_max_concurrency(4));

let docs = vec![Document::new("Revenue grew 3% year over year.")];
let enhanced = enhancer.enhance_documents(&docs).await;

Note: The context sentence is written to metadata["contextual_context"], retrievable and auditable; then index the enhanced docs as usual with index_documents(enhanced).

6.10 SemanticCache

CachedRetriever wraps any RetrieverTrait: a lexical hit (identical query string) returns the cache and skips embedding; otherwise it computes cosine similarity against cached entries and, past the threshold, treats the query as a synonym hit. Drastically lowers the cost of repeated queries.

Core value: semantically equivalent queries hit the cache directly, no repeated embedding + retrieval each time.

Two-Level Hit

Lexical hit is zero cost; semantic hit is judged by cosine threshold

k in Identity

Same query with different k caches separately, no cross-use

Capacity / TTL

with_max_entries FIFO capacity + optional with_ttl expiry

Auto Invalidate

add_documents auto-invalidates, corpus updates stay clean

CachedRetriever usage

rust 
use langchainrust::retrieval::{CachedRetriever, SemanticCacheConfig};

let cached = CachedRetriever::new(
    Arc::new(inner_retriever),   // any RetrieverTrait
    Arc::new(embeddings),        // to embed queries
    SemanticCacheConfig::new()
        .with_threshold(0.95)    // semantic hit threshold
        .with_max_entries(256)   // FIFO capacity
        .with_ttl(Some(Duration::from_secs(600))),
);

let docs = cached.retrieve("apple", 3).await?; // miss → retrieve and cache
let fast = cached.retrieve("apple", 3).await?; // lexical hit, zero cost

Note: After a corpus update, invalidate manually via cache().invalidate() or rely on add_documents auto-invalidation. With guardrails, wrap GuardedRetriever on the inside.

Appendix.12 Best Practices

01 Agent Selection

Use FunctionCallingAgent first (more reliable). Use ReActAgent for local models.

02 Model Selection

Agents: gpt-4 recommended. Simple chat: gpt-3.5-turbo. Gemini for multimodal.

03 Memory Selection

Long conversations: SummaryBufferMemory. Short: BufferMemory. Very long: ContextWindow.

04 RAG Strategy

Simple: RetrievalQA. Quality-critical: CorrectiveRAG. Relationship-heavy: GraphRAG. Adaptive: AdaptiveRAG.

05 Model Routing

Use RouterLLM with Fallback for reliability, LowestCost for budget, LeastLatency for speed.

06 Caching

Enable LLM cache for repetitive queries. Use Batch API for offline bulk processing (50% cost reduction).

07 Document Strategy

Few small docs → Stuff. Many docs → MapReduce. Accuracy critical → MapRerank. Relationships → GraphRAG.

08 Observability

Use Tracing (Tracer + SpanGuard) for production monitoring. OTel backend for distributed tracing.

09 Security

Use Guardrails for input/output validation. Use environment variables for API keys. Never hardcode.

10 CRAG Grading

Use with_grader_llm() to inject a different LLM for hallucination detection, avoiding self-verification bias.
